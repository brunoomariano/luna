# ADR-0039: A role per stage, and what carries context between them

**Status:** Accepted
**Date:** 2026-08-11

## Context

Today one agent lives for a whole task. That was not designed — herdr refusing a repeated
name revealed it (ADR-0036), and it stuck because it worked: the agent keeps whatever it
built across stages.

It also means the agent that wrote the code is the agent that reviews it, which
INV-core-7 forbids. `src/stock/roles/` is empty, and the invariant is described rather
than held.

The obvious objection to a role per stage is that a fresh agent starts blind. That
objection is real and already answered, twice:

- **The contract answers it structurally.** Every stage declares what it `produces`, and
  the next stage declares what it `requires`. That is not a summary of the work — it is
  the work, checked on entry and exit (INV-core-3). A prose handoff would be the
  degradation INV-core-6 exists to prevent.
- **Durable memory answers the rest.** The project already runs `ai-memory`, scoped by
  `.ai-memory.toml`. What one agent learned is readable by the next without either of
  them summarising it for the other.

## Decision

**Each stage runs the agent its role names. Context crosses by contract and by durable
memory — never by prose.**

An agent is born for its stage and may end when the stage closes. What survives it:

| What crosses | How | Why not prose |
|---|---|---|
| the artifacts the stage owed | `produces` → `requires`, checked | the contract *is* the handoff (INV-core-6) |
| what was proven, and at what scope | the evidence record | a claim is not a check (ADR-0028) |
| what the agent learned along the way | durable memory, task-scoped | the next agent reads the real note |
| what the flow decided | the append-only log | replay, not recollection |

**A role names an agent kind and a skill set, not a person.** `build` and `code-review`
must resolve to different agents for INV-core-7 to hold — that is the point of the
change, and the static check should refuse a flow where a review stage names the same
role as the stage it reviews.

Two consequences worth stating before they are discovered:

1. **The prompt has to carry the handoff.** It is `"Task LUNA-1, stage build."` today,
   which was sufficient when one agent remembered everything and is not sufficient now.
   It must name the task, the stage, what the stage owes, and where to read what it
   requires. The body is generated by Luna, not written by an agent (INV-core-6).

2. **Durable memory must resolve inside the worktree.** `.ai-memory.toml` exists at the
   repository root, and resolution walks up from the working directory — which breaks in
   a sibling worktree, exactly where every task runs (`wt-<repo>-<id>`). The file's own
   comment already names this failure. Luna has to make the scope reach the agent rather
   than assume it.

## Alternatives considered

- **One agent per task, roles later** — rejected, though it is what exists and it costs
  nothing today. It leaves INV-core-7 as prose: an agent that merely *tends not to*
  review its own work does not satisfy the invariant, and the acceptance criteria say so.
- **A role per stage with a prose handoff between them** — rejected. It is the obvious fix
  for the context loss and it is the exact degradation INV-core-6 forbids: every hop
  rewrites the message, and it decays along the chain. The contract already carries what
  must cross.
- **Keeping the agent alive across stages and changing its role by prompt** — rejected.
  It preserves context and defeats the purpose: the reviewer would be the same process,
  with the same conversation, that wrote the code. INV-core-7 is about independence, not
  about instructions.

## Consequences

- **Positive:** INV-core-7 becomes checkable rather than hoped for. Each stage gets an
  agent chosen for it, so a review runs on a reviewer rather than on whatever happened to
  start first.
- **Negative / costs:** more agents started and stopped per task, which is more herdr
  traffic and more startup races of the kind ADR-0036 already had to handle. And an agent
  that ends takes its unwritten context with it — anything not in the contract, the
  evidence or durable memory is gone by design.
- **Impacts:**
  - `src/stock/roles/` gains real content, and a role maps to one of herdr's 21 agent
    kinds (ADR-0031);
  - `herdr.Node`'s single `Agent` field becomes a lookup by stage;
  - the agent name is per stage rather than per task, so `agentName` grows the stage —
    and herdr's uniqueness rule makes a collision loud rather than silent (ADR-0036);
  - the static flow check should refuse a review stage whose role matches the stage it
    reviews, which is INV-core-7 expressed as a test rather than a hope.
